# Beeline Route Planning — прототип диспетчеризации выездов

Полный стек: FastAPI + OR-Tools (VRPTW) backend, React + Leaflet frontend, обработанные
данные трёх регионов (205 заявок, 34 инженера). Кейс «Контрольное распределение».

## Быстрый старт
    docker compose up --build        # backend :8000, frontend :5173
Или локально (два терминала):
    cd backend && pip install -r requirements.txt && uvicorn app.main:app --reload
    cd frontend && npm install && npm run dev        # прокси /api -> :8000

## Демо-сценарий (5–7 минут)
1. Загрузка набора данных (все регионы / один регион)
2. «Запустить планирование» → назначения появляются на карте
3. Карта: маршрут каждого инженера своим цветом, точки-номера остановок, маркеры старта
4. Клик по точке → объяснение: почему этот инженер, какие ограничения сработали
5. Перепланирование: ⚡ срочная заявка / ✕ отмена / 🚫 инженер недоступен → подсветка diff
6. Вкладка «Сравнение с baseline» — два обязательных метрики рядом

## Три группы ограничений (реализованы в app/constraints.py)
- Квалификация: навык заявки ∈ навыкам инженера (local / connection / emergency)
- Время: дорога + работа вписываются в смену, визит начинается внутри окна заявки
- Ресурс: если заявка требует тип транспорта — он совпадает (null = «без ограничения»)

## Два обязательных метрики (app/metrics.py)
1. Минимум задействованных инженеров
2. Пробег на инженера + суммарный — против базовой линии (arrival order, first-fit)

## Допущения (явно заявленные)
| Допущение | Обоснование |
|---|---|
| Координаты | кэш геокодинга: scripts/build_data.py --geocode (Nominatim + нормализация адресов); fallback — центроид района + детерминированный джиттер, флаг coord_approx |
| Дистанции/время | haversine × 1.35 дорожный фактор; скорости: авто 30, ОТ 25, вело 15, пешком 5 км/ч |
| Инженеры | файла нет → синтез из 34 исторических бригад контрольных файлов: навыки из типов их заявок, смена = слоты ±2ч, старт = домашний район |
| Депо | адреса офисов из footer-строк исходных файлов |
| Длительность/приоритет | маппинг от типа HD (Авария 90 мин → urgent); окна из колонок Начало/Окончание |
| Маршрут | старт в точке инженера, возврат не требуется (по спецификации кейса) |

## API
    GET  /api/meta
    GET  /api/tickets?region=
    GET  /api/engineers
    POST /api/plan     {region, algorithm: solver|baseline}
    POST /api/replan   {region, algorithm, event: {type: new_urgent_ticket|cancel_ticket|engineer_unavailable, ...}}

## Структура
    backend/app/        solver (OR-Tools + жадный fallback), baseline, metrics, explain, replan
    backend/data/       processed (tickets/engineers/depots/coords) + raw (6 исходных CSV)
    frontend/src/       React SPA: карта, KPI, таблицы, перепланирование, сравнение
    scripts/build_data.py  воспроизводимый пайплайн raw -> processed
